# Stage 2 policy testing preparation — no live execution

The six synthetic documents, expected complete IR envelopes and deterministic
journeys are in `tests/fixtures/stage2/policy_cases.json`. They were authored offline,
not generated by a provider. Tests validate Pydantic IR, closed vocabulary, source
grounding, expected decision boundaries, and the real compile endpoint using SDK
MockTransport. No live inference is necessary for these automated tests.

| Document | Expected extraction and behavior | Fields / operators | Future live purpose |
| --- | --- | --- | --- |
| simple_refund.md | ALLOW refund through day 30 inclusive; days 0/30 allow, day 31 falls back to DENY | days_since_delivery / LTE | Optional extraction-quality check |
| damaged_replacement.md | ALLOW replacement through day 14 only for a reported damaged item; undamaged/day 15 fall back to DENY | item_damaged, days_since_delivery / IS_TRUE, LTE; nested all | Optional two-condition extraction |
| cancelled_replacement.md | ALLOW refund after a replacement cancellation; no invented deadline or obligation to refund automatically | replacement_cancelled / IS_TRUE | Optional cancellation semantics extraction |
| combined_policy.md | Two grounded rules, refund through day 30 and replacement through day 14; no conflated trigger/decision | days_since_delivery / LTE; REFUND_REQUESTED and REPLACEMENT_REQUESTED | Optional multi-rule extraction in ONE request |
| strict_boundary.md | Refund ALLOW with LT 30; day 29 allows, day 30 does not; no silent LTE substitution | days_since_delivery / LT | Optional strict-vs-inclusive boundary check |
| ambiguous_window.md | Reject or seek human clarification; never invent a numeric duration for “reasonable time” | No asserted numeric predicate | Optional safe-failure/ambiguity assessment |

Source doc_name must match the document, every nonempty quote must be grounded in
its input, required Rule fields must validate, and unsupported values must fail.
The cancellation test follows the existing engine's REPLACEMENT_CANCELLED state
transition; it does not establish real-world fulfillment obligations. DENY beyond
an ALLOW rule is the configured engine fallback, not an invented extracted rule.

The ambiguous fixture returns no rules and the live endpoint rejects it locally
with no repair request. A real model might produce a syntactically valid but
unjustified condition; schema/grounding alone cannot establish semantic accuracy.
Always inspect its threshold, effect, conditions, exceptions and source manually.

## Execution policy for later approval

No batch live runner was added. Keep server live mode OFF during preparation.
After a fresh explicit authorization, enable the owner-controlled API, enter ONE
document, check consent, and click Compile once. Review the usage and validated
draft before activating. Stop on failure and do not repair, fall back, or rerun
automatically. Changing an example or typing never calls the model.

The original fixed synthetic CLI smoke runner is still independent of the API.
It does not accept arbitrary Stage 2 documents and must not be used as a batch tool.
The next live action would exercise the new UI/API integration, not merely repeat
the already-passing fixed CLI test.
